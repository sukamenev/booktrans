# Перевод

Самая долгая и дорогая стадия. Книга делится на куски по несколько тысяч
слов, каждый переводится отдельным запросом, ответ ложится в свой файл.

## `tr/NNNN.json` — черновик куска

```json
{
 "index": 1,
 "model": "claude-opus-5",
 "cost_usd": 0.355,
 "tr":   { "s06.b0001": "ГЛАВА 1", "s06.b0002": "Порт-Харкорт, <i>Нигерия</i>" },
 "src":  { "s06.b0001": "e0e57fcf7396", "s06.b0002": "a41b90c7d215" },
 "footnotes": [],
 "saved": 1786755983.6
}
```

| ключ | что это |
|---|---|
| `index` | номер куска |
| `model`, `cost_usd` | кто перевёл и почём; из этого складывается отчёт о расходе |
| `tr` | **блок → перевод**; главное содержимое |
| `src` | блок → отпечаток **оригинала** |
| `footnotes` | сноски, предложенные переводчиком по ходу |
| `saved` | время записи; им решается спор двух файлов за один блок |

`tr` и `src` при перезаписи файла сливаются со старыми — см.
[общие правила](common.md).

### Что считается сделанным

Кусок пропускается, если **каждый** его переводимый блок есть в `tr` и его
отпечаток сошёлся с нынешним оригиналом:

```python
if all(b["id"] in have and have[b["id"]] in (None, fingerprint(b["text"]))
       for b in translatable(c["blocks"])):
    skipped += 1
```

`None` — это файлы прежних выпусков, у которых `src` нет вовсе: сверить
нечем, верим на слово, но говорим об этом вслух.

Один изменившийся блок отправляет к модели весь кусок: переводчику нужен
связный текст, а не выборка абзацев.

### Что в кусок не идёт

`translatable()` отбирает блоки для перевода. Не идут: картинки,
разделители, листинги и всё помеченное `asis` — библиография, предметный
указатель. Заголовки переводятся отдельным проходом, см. ниже.

### Отказ и обрыв

Модель иногда возвращает не все блоки. Если пропущенное идёт **сплошным
хвостом** — это обрыв: модель дошла до какого-то места и дальше писать не
стала, обычно упёршись в содержание. Дважды на одном месте — уже не
случайность, и кусок передаётся следующей модели цепочки.

Пустой файл в таком случае не пишется: он лёг бы как сделанная работа, и
следующий запуск обошёл бы кусок стороной.

### Заслоны разбора

Ответ со всеми метками ещё не перевод. Три класса брака, где счёт блоков
сходится, ловятся до записи на диск, и кусок уходит на повтор:

- **обрубок** — под меткой длинного блока пара слов: модель молча выкинула
  сцену, но продолжила со следующего блока. Порог — доля длины оригинала
  (`STUB_SHARE`), включается от `STUB_MIN` знаков: короткий блок честно
  короток;
- **близнецы** — соседним блокам достался один и тот же перевод при разных
  оригиналах: модель сбилась на ряду похожих абзацев, один оригинал остался
  непереведённым;
- **сдвиг** — под меткой N перевод блока N−1, последний блок куска пропал.
  Тексты все разные и поодиночке правдоподобны; выдаёт строй длин: длина
  перевода следует за длиной оригинала, и окно соседних блоков, где каждый
  перевод ближе к длине чужого оригинала, чем своего, — не случайность
  (`SHIFT_*` в `tune.py`). На живой книге так молча съехали 26 блоков из 38.

Все три — арифметика по длинам, без запросов к моделям и знания языков.

## `headings.json` — заголовки

Заголовки переводятся не с текстом, а одним запросом на всю книгу:

```json
{ "CHAPTER 1": "ГЛАВА 1", "Port Harcourt, Nigeria": "Порт-Харкорт, Нигерия" }
```

Ключ — заголовок оригинала, значение — перевод. Так потому, что их немного
(десятки), а совпадать между собой они обязаны дословно: десять вхождений
одного имени рассказчика не должны выглядеть по-разному. Вдобавок короткая
строка в начале запроса принимается моделью за шапку промпта и молча
теряется.

Файл **правится руками**: поправили название главы — сборка возьмёт новое,
переводить заново ничего не нужно.

## `code.json` — комментарии в листингах

Только для книг с кодом и при `--code comments`.

```json
{ "s12.b0034": "x = 1  # сосчитать предметы" }
```

Блок → листинг целиком, с уже подставленными переводами комментариев.

Код в переводе остаётся как есть: имена, отступы, строковые литералы.
`print("Hello")` перевести нельзя — двумя абзацами ниже книга показывает, что
она печатает. А комментарий — проза, и в учебнике на ней держится половина
объяснения.

Комментарии **ищет** модель (знаков комментария у языков сотни), но
**подставляет** перевод программа: названный моделью кусок обязан найтись в
названной строке, и заменяется ровно он. Не сошлось — строка остаётся как
была: непереведённый комментарий заметен и поправим, испорченный код — нет.

## `ocrfix.json` — починка распознавания

Появляется, если книга распознана с бумаги.

```json
{ "s22.b0008": [["GX pNiWpbb5", "GXpNiWpbb5"]], "s22.b0009": [] }
```

Блок → список замен `[было, стало]`. Пустой список значит «смотрели, чинить
нечего» — потому проход и не возвращается к этому блоку.

Чинится **оригинал и до всего остального**: иначе разведка соберёт справочник
по испорченному, а переводчик будет разбирать порчу молча и всякий раз
по-своему. Порог сходства `FIX_NEAR` не даёт подменить слово вместо починки:
«hitr«d iietion» → «Introduction» это 0.67, а «thou art» → «you are» —
осовременивание автора, которого не просили, — 0.62.

Отметки времени этот файл не получает: он сплошная карта «блок → работа»,
спорить ему не с кем.

## `prompts/` — запросы как есть

    ru/prompts/0042.txt         что ушло переводчику
    ru/prompts/0042.edit.txt    что ушло редактору
    ru/prompts/0042.notes.txt   что ушло на сноски
    prompts/structure.txt       что ушло на разбор стилей

Первые три лежат в папке языка, последний — в общей: стили книги языка
перевода не знают, и разбор их у всех языков один.

Ни на что не влияют, читаются только человеком. Когда перевод куска вышел
странным, это первое место, куда стоит посмотреть: видно и справочник, и
конспект, и хвост предыдущего куска — всё, что модель имела перед глазами.
