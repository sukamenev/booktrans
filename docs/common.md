# Общие правила

Три вещи повторяются во всех файлах: чем называется блок, чем доказывается,
что работа над ним сделана, и как устроены файлы кусков. Разобравшись
однажды, остальное читается легко.

## Номер блока

Книга разбирается в **плоский список блоков**. У каждого номер вида
`s26.b0049` — двадцать шестой раздел, сорок девятый блок в нём. Картинки
нумеруются отдельным рядом: `s26.i0003`.

Номер **позиционный**: он говорит, где блок стоит, а не что в нём написано.
Отсюда главное следствие:

> Перечитали книгу с другой разметкой — и тот же номер указывает на другой
> текст.

Так бывает чаще, чем кажется: сменилась версия конвейера, поправили
`structure.json`, разметка сочла колонтитулом то, что раньше считала абзацем.
Поэтому одного номера мало, чтобы признать работу сделанной, — нужен ещё
отпечаток.

## Отпечаток

`fingerprint(text)` — двенадцать шестнадцатеричных цифр от текста, из
которого выброшены разметка и лишние пробелы:

    fingerprint("Текст  <b>жирный</b>\nдальше")  ==  fingerprint("Текст <b>жирный</b> дальше")

Разметка не считается нарочно: `<i>` и `<b>` вокруг слова не делают текст
другим. А вот правка распознавания — делает, поэтому сверять отпечатки надо
**после** `apply_fixes`.

Отпечаток хранится рядом с работой, в поле `src`. Смысл у него везде один —
«вот по какому тексту это делали», — но текст в разных проходах разный:

| файл | `src` — отпечаток чего | о чём спрашивает |
|---|---|---|
| `tr/NNNN.json` | **оригинала** | не изменился ли исходный абзац → переводить заново |
| `ed/NNNN.json` | **черновика перевода** | не перевели ли заново → править заново |

Редактура делается по переводу, а не по оригиналу, — оттого и разница.

## Файлы кусков

Перевод, редактура и сноски идут кусками по несколько тысяч слов. Каждый
кусок — свой файл, названный его номером: `tr/0042.json`.

**Имя файла — не идентификатор работы.** Нарезка между прогонами меняется:
убрали из книги повторы — и восемьдесят первый кусок стал восьмидесятым.
Поэтому все проходы читают эти файлы **по номерам блоков**, а не по именам
файлов, и собирают книгу из всех файлов сразу.

### Запись поверх существующего

Новый кусок под тем же именем не стирает работу прежнего. При записи
словари сливаются со старыми:

    BY_BLOCK = ("tr", "src", "edits")

Всё, что перечислено здесь, — карты «блок → работа», и они накапливаются.
Прочие поля заменяются.

> **Отсюда правило: сделанное считают по тому, что сливается.**
>
> В файлах редактуры есть ещё список `blocks` — перечень блоков куска. Он
> список, а не карта, и при перезаписи заменяется. Пока готовность читалась
> по нему, работа прежней нарезки выглядела несделанной: на живой книге так
> потеряли запись о 201 блоке, и каждый прогон переделывал горстку кусков,
> стирая запись о следующей. Теперь готовность читается по `src`.

### Отметка времени

Поле `saved` — время записи. Один блок может лежать в двух файлах сразу
(нарезка сдвинулась, старый файл остался), и спор решается по свежести, а не
по большему номеру. У файлов от прежних выпусков отметки нет — тогда берётся
время самого файла.

Сплошные карты «блок → работа» (`ocrfix.json`, `code.json`) отметки не
получают: спорить им не с кем, а `saved` лёг бы туда как блок с таким именем
и уронил проход, считающий работу по блокам.

## Как читается «сделано»

Пример — редактура:

```python
for n in sorted(os.listdir(f"{work}/ed")):
    x = json.load(open(f"{work}/ed/{n}"))
    bl = x.get("blocks") or []
    at = x.get("stopped_at") or len(bl)
    fp = x.get("src") or {}
    if fp:
        got = {i for i, f in fp.items() if f == fingerprint(raw.get(i, ""))}
        ready |= got - set(bl[at:])
    else:
        ready.update(bl[:at])        # файлы прежних выпусков
```

Блок готов, если **есть запись** и **отпечаток сошёлся**. Всё остальное —
частности: `stopped_at` вычитает хвост оборванного куска, ветка `else`
принимает на веру файлы, писанные до появления отпечатков.

А решение принимается **по кускам**: один неготовый блок отправляет к модели
весь свой кусок целиком. Дробить нельзя — редактор правит связки и
местоимения, и ему нужен связный текст, а не выборка абзацев.

## Перерыв и продолжение

Прервать можно в любой момент: всё сделанное уже на диске. Долгие проходы,
идущие не кусками, дописывают промежуточный файл `*.part.json`
(`marks.part.json`, `scout.part.json`) — с ним прогон продолжается с места
обрыва, а не с начала.

Запись атомарна: файл пишется во временный и подменяется целиком. При
`--jobs > 1` соседний поток иначе прочёл бы половину и упал на разборе json.
