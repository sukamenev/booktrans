## Pdftotext как производитель страниц

Сейчас у pdf два чтения. Основное — распознавание: модель пишет файлы
страниц в [формате страницы](reading.md#формат-страницы), чтение разбирает
их. Запасное — текстовый слой целиком, с разметчиком: им книга читается,
когда в цепочке `--ocrmodel` нет ни одной модели. Pdftotext в цепочке с
моделями подменяет только отказавшую страницу и отдаёт её одними абзацами.

Мысль — один путь: любой источник страниц пишет их в одном формате, дальше
всё одинаково.

1. **Pdftotext пишет страницы по договору.** Разбор слоя и разметчик идут на
   всю книгу сразу — колонтитул узнаётся по повторяемости, оглавление
   сверяется с главами, — а затем пометки переводятся в markdown и
   раскладываются по файлам страниц: заголовок — решёткой, оглавление —
   пометкой, листинг — блоком кода, мусор выбрасывается.
2. **Одно чтение pdf.** Ссылки из аннотаций, картинки из pdfimages с
   расстановкой по страницам, обложка, название и размер страницы из
   метаданных переезжают в чтение страниц; отдельное чтение по слою
   уходит. Две pdf-книги корпуса переезжают вместе с ним.
3. **Выбор по странице.** Pdftotext первым в цепочке, модель — только там,
   где слоя нет или он испорчен. Нужна оценка порчи на страницу: сейчас
   она одна на книгу. Сейчас pdftotext первым в цепочке отключает модели
   совсем.

Цена: много кода, а выигрыш получает запасной путь — основной идёт через
модель. Как будет выглядеть книга, прочитанная по слою, заранее не
предсказать. Браться, если понадобится экономить распознавание на толстых
книгах с хорошим слоем: только третий шаг даёт выгоду в деньгах, и он
требует первых двух.
