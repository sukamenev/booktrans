# Редактура, сверка и сноски

Редактура читает **только перевод**, оригинал ей намеренно не показывают:
иначе правка идёт в сторону чужого синтаксиса, а не хорошего русского.
Отсюда и устройство файлов — правка хранится парой «было и стало», а её
готовность считается по отпечатку перевода, а не оригинала.

У слепоты есть цена: место, неверное по существу, редактор не правит, а
выписывает замечанием. Разрешает такие замечания отдельный этап — сверка,
единственный, кто видит обе стороны; о ней ниже.

## `ed/NNNN.json` — правки куска

```json
{
 "index": 1,
 "model": "claude-opus-5",
 "cost_usd": 1.329,
 "notes": "1. **Главное. Адресат «ты» переведён в мужской род**…",
 "blocks": ["s03.b0002", "s05.b0002", "s05.b0003"],
 "src":   { "s05.b0004": "e49ce177b5f9" },
 "edits": { "s05.b0005": { "old": "Моей жене Лоре", "new": "Моей жене Лауре" } },
 "saved": 1786836737.0
}
```

| ключ | что это |
|---|---|
| `index` | номер куска |
| `model`, `cost_usd` | кто правил и почём |
| `notes` | замечания редактора человеку, свободным текстом |
| `blocks` | перечень блоков куска — **список**, при перезаписи заменяется |
| `src` | блок → отпечаток **черновика перевода**, по которому правили |
| `edits` | блок → `{"old": …, "new": …}` — только изменённые блоки |
| `stopped_at` | если правка оборвалась: место обрыва в `blocks` |
| `saved` | время записи |

Сливаются при перезаписи `src` и `edits`; `blocks` — нет. Поэтому файл
бывает «шире» своего куска: в одном живом примере `blocks` — 67 имён, а
`src` — 97 и `edits` — 33. Это следы нескольких нарезок, и читать сделанное
надо по `src`. Подробнее — в [общих правилах](common.md).

### Почему правки хранятся парой

`old` и `new` вместе позволяют показать сделанное (`--diff`), наложить
правку поверх черновика по номеру блока и откатить её, не переводя заново.
Сборка берёт `new`, но только если `old` совпал с черновиком под рукой:

```python
for k, e in json.load(open(p))["edits"].items():
    if k in tr and tr[k] == e.get("old", tr[k]):
        tr[k] = e["new"]
```

Несовпавшая правка — **сирота**: блок перевели заново, а карты `edits` при
перезаписи сливаются, и старая правка переживает свой черновик. Ложиться
поверх нового перевода ей нельзя — на живой книге сирота вернула в текст
сцену, выброшенную вместе со старым переводом. Пропущенная сирота не
потеря: по отпечаткам блок числится неотредактированным, и следующий
проход правки переделает его честно.

Изменённых блоков обычно четверть-треть куска: редактор по замыслу
возвращает только то, что правил, а не весь текст.

### `stopped_at` — оборванная правка

Беда в том, что оборванный ответ выглядит ровно как «посмотрел всё, править
нечего». Отличают по месту последней правки: на здоровом куске они рассыпаны
по всему тексту, а когда модель упирается в содержание — обрываются в начале
и дальше пусто. Замерено: обычный кусок — 27 правок из 70, последняя на
70-м блоке; кусок со спорной сценой — 2 из 41, обе в первых двух.

Тогда пишется `stopped_at`, и хвост после него готовым не считается. В `src`
такой хвост **не попадает** — иначе сошёл бы за отредактированный.

Переспрашивать ту же модель бессмысленно: она упрётся в то же место и
возьмёт деньги зря. Поэтому такой кусок пропускается, пока редактировать
будет она же; сменили модель в цепочке — возьмётся заново.

### Какой моделью

Обычный кусок правит редактор из профиля — нарочно другая модель, чем
переводчик: своих калек автор не видит. Одно исключение: кусок, переведённый
запасным **после отказа** основного. Перевод записывает в `tr/NNNN.json`
пометку `after_refusal` и список `refused_by` — имена отказавшихся моделей.
Такой кусок идёт обычной цепочке редакторов за вычетом отказавшихся: отказ
вызван содержанием, и на правке он повторился бы — причём тихо, обрывом в
начале, который не отличить от «править нечего». Если отказалась вся
цепочка, кусок достаётся переведшей модели: содержание она заведомо приняла.
Это самоправка, но как страховочное дно, а не первый выбор — раньше кусок
сразу уходил переведшей, и запасной переводчик правил собственный перевод.
В файлах, записанных до появления `refused_by`, имён нет, и такой кусок
по-старому правит переведшая модель: угадать редактора, который откажется
тихо, дороже самоправки.

## `nt/NNNN.json` — сноски отдельным проходом

Обычно сноски делает редактура: она и так держит оригинал с переводом рядом.
Отдельный проход `notes` остаётся для случая, когда редактуру пропускают.

```json
{
 "index": 1,
 "model": "claude-opus-5",
 "cost_usd": 0.21,
 "notes": [
  { "block": "s01.b0002", "kind": "term",
    "term": "дефект", "text": "Пояснение в одну-четыре фразы." }
 ]
}
```

| поле сноски | что это |
|---|---|
| `block` | к какому блоку она относится |
| `kind` | `reference` — отсылка, `fact` — расхождение с действительностью, `term` — реалия, `source` — откуда цитата и чей перевод |
| `term` | слово или имя, к которому сноска |
| `text` | сама сноска, законченная и самодостаточная |

Здесь `notes` — **список сносок**, а в файлах редактуры `notes` — **строка с
замечаниями человеку**. Имя одно, содержимое разное; при чтении это
приходится различать.

### Как сноски собираются в книгу

Собирает их сборка, `all_notes`, из трёх мест разом: `footnotes` файлов
перевода, `footnotes` файлов редактуры и `notes` файлов `nt/`. Правила:

- **одно понятие объясняется один раз**: повторный `term` (без учёта
  регистра) отбрасывается, остаётся самый ранний по книге;
- **одна сноска на блок**: несколько сносок к одному абзацу склеиваются в
  одну, их термины сохраняются списком `terms`;
- **текст начинается с термина**: «Vesti — российский телеканал…». По
  ссылке читалка показывает сноску одну, без абзаца вокруг, и без термина
  это ответ без вопроса. Текст, начатый с термина (пусть и склонённого —
  сверка по основе слова), не трогается;
- к цитате по чужому переводу дописывается оговорка `source_caveat` — что
  машина не может подтвердить дословность.

### Куда встаёт знак сноски

По `terms` сборка вставляет в текст блока невидимую метку сразу после
термина (`output.anchor_note`), и каждый формат ставит на её месте свой
знак: `<sup>` в epub и html, `type="note"` в fb2, `[^n]` в markdown,
`\footnote` в LaTeX. Термин ищется по основам слов, поэтому склонённая
форма находится; не нашёлся — знак остаётся в конце абзаца, как было
всегда: это честнее знака не у того слова.

## `vf/NNNN.json` — сверка замечаний с оригиналом

Замечания редактора кончаются словами «сверить с оригиналом» не случайно:
оригинала у него нет. Сверщик — единственный, кто видит обе стороны: ему
дают замечание, оригинал названных в нём блоков и их перевод. По каждому
блоку он выносит вердикт:

| вердикт | что происходит |
|---|---|
| `author` | перевод верен, ошибся автор: текст не трогается, истина уходит в сноску `fact` |
| `translation` | перевод разошёлся с оригиналом: блок исправляется |
| `dismiss` | подозрение пустое: снимается с объяснением |
| `unsure` | сверка вопроса не решает: остаётся человеку в `review.md` |

```json
{
 "index": 9,
 "model": "gpt-5.6-sol",
 "cost_usd": 0.04,
 "remark": "a1b2c3d4e5f6",
 "src":   { "s09.b0003": "e49ce177b5f9" },
 "notes": "s09.b0003: ошибка автора → сноска. «…пяти устойчивых точек…» — устойчивы только две.",
 "footnotes": [ { "block": "s09.b0003", "kind": "fact", "term": "точек Лагранжа",
                  "text": "«…пяти гравитационно устойчивых точек…» — автор ошибся: устойчивы только L4 и L5." } ],
 "edits": { "s39.b0011": { "old": "…объёма…", "new": "…массы…" } }
}
```

| ключ | что это |
|---|---|
| `remark` | отпечаток замечания, по которому сверяли |
| `src` | блок → отпечаток сверявшегося текста (перевод с наложенной редактурой) |
| `notes` | резолюции по блокам; в `review.md` они встают вместо замечания |
| `footnotes` | сноски «ошибка автора» — в книге подписываются «— *Прим. ред.*» вместо переводческого префикса |
| `edits` | исправления перевода — ложатся поверх правок редактора |

Готовность считается по паре отпечатков: изменилось замечание **или** текст
блока — сверяется заново. Замечание, в котором не назван ни один
идентификатор блока, не сверяется вовсе: его не к чему приложить, и оно
остаётся человеку, как раньше.

Сверяет по умолчанию **цепочка редактора**; ключ `--verifier` переопределяет.
Переводчику эту работу отдавать нельзя: вердикт «ошибся перевод» выносится
его собственной работе, и судья в своём деле склонен винить автора. Редактор
же к спорным блокам непричастен — он их сознательно не правил.

## `review.md` — замечания редактора одним файлом

Собирается на сборке из полей `notes` всех файлов `ed/`. Конвейеру не нужен
вовсе — он для человека, который будет вычитывать книгу. Сверенные замечания
показываются не в исходном виде, а резолюциями сверщика: что подтверждено
сноской, что исправлено, что снято — человеку остаётся нерешённое и след
решённого.

    ## кусок 0024
    - Сноска о Старом Вашингтоне даётся на случай, если город здесь…
    - «Retreat house» переведено как «скит», по справочнику…

Тут редактор говорит то, чего не стал решать сам: где остались два законных
варианта, где он взял на себя термин, которого нет в справочнике, где нашёл
ошибку черновика. Пересобирается при каждой сборке.

Хвост ответа модели чистится от «строительных лесов» — своей оградки,
служебного тега (`</invoke>`, `</summary>`), закрывающей скобки к нашей же
метке. Замерено: у Claude такой мусор приходил в 8% кусков (после перехода
на метки `[[[ ]]]` — в 1%), у Gemini и Codex не приходил ни разу.
