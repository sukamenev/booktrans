# Формат рабочих файлов

Всё, что конвейер знает о книге, лежит в **рабочей папке** рядом с ней:

    Книга.epub
    Книга.work/            ← сюда

Имя папки — имя книги с расширением `.work`; переопределяется ключом `--work`.
Папку можно унести на другую машину, переименовать книгу, обновить конвейер —
работа не пропадёт. Удалить папку значит начать книгу заново и заплатить за
неё второй раз.

## Зачем это описано

Прогон стоит часы и деньги, и почти всякая правка конвейера сводится к
вопросу «что уже сделано и по чему это видно». Ответ лежит в этих файлах.
Здесь описано, что в них хранится, кто их пишет и по какому правилу читает.

## Оглавление

Начинать стоит с [общих правил](common.md): номер блока, отпечаток и файл
куска повторяются во всех стадиях, и, разобравшись в них однажды, остальное
читается легко.

| | о чём |
|---|---|
| [Общие правила](common.md) | номера блоков, отпечатки, файлы кусков, порядок записи |
| [Чтение книги](reading.md) | `book.json`, `structure.json`, `marks.json`, `toc.json`, картинки |
| [Разведка](scout.md) | `scout.md`, `scout.json`, `state.json` |
| [Перевод](translate.md) | `tr/`, `headings.json`, `code.json`, `ocrfix.json` |
| [Редактура и сноски](edit.md) | `ed/`, `nt/`, `review.md` |
| [Сборка и проверки](build.md) | `terms.json`, `fixups.json`, `source.json`, отчёты |

## Все файлы разом

| файл | стадия | пишет | зачем |
|---|---|---|---|
| `book.json` | чтение | `extract.read_book` | книга блоками: метаданные и текст |
| `cover.bin` | чтение | `extract` | обложка как есть |
| `images/` | чтение | `extract` | картинки книги |
| `pdf_pages/` | чтение | `extract.ocr` | страницы pdf в png и их расшифровка |
| `structure.json` | чтение | `pipeline.detect_structure` | карта «тег\|класс → вид блока» |
| `marks.json` | чтение | `pipeline.format_marks` | вид каждого абзаца pdf и txt |
| `marks.part.json` | чтение | `format.plan` | недоделанная разметка, для продолжения |
| `toc.json` | чтение | `pipeline._check_toc` | названия глав из оглавления книги |
| `scout.md` | разведка | `pipeline.scout` | справочник по книге; идёт в каждый запрос |
| `scout.json` | разведка | `pipeline.scout` | какая модель его собрала |
| `scout.part.json` | разведка | `pipeline.scout` | разборы частей, для продолжения |
| `state.json` | перевод | `pipeline.translate` | сводки и термины по кускам, сжатый конспект |
| `headings.json` | перевод | `pipeline.headings` | заголовок оригинала → перевод |
| `tr/NNNN.json` | перевод | `pipeline.translate` | черновик перевода куска |
| `code.json` | перевод | `pipeline.code_comments` | листинги с переведёнными комментариями |
| `ocrfix.json` | правка OCR | `pipeline.fix_ocr` | починка порчи распознавания |
| `ed/NNNN.json` | редактура | `pipeline.edit` | правки и замечания редактора |
| `nt/NNNN.json` | сноски | `pipeline.notes` | сноски отдельным проходом |
| `prompts/` | все | каждый проход | запросы как есть, для разбирательств |
| `source.json` | сборка | `pipeline.note_source` | чем читали и размечали — для раздела «О переводе» |
| `review.md` | сборка | `build.review_report` | замечания редактора одним файлом для человека |
| `terms.json` | сборка | **человек** | термины, соблюдение которых проверяется |
| `fixups.json` | сборка | **человек** | сквозные замены в готовом переводе |
| `prompt_meta.json` | все | `cli` | указания заказчика, чтобы не терялись при пересборке |
| `running.pid` | все | `cli` | замок: две книги разом в одной папке не идут |

Два файла из этого списка пишет не конвейер, а человек: `terms.json` и
`fixups.json`. Они описаны в [сборке](build.md).

## Чего в рабочей папке нет

**Готовой книги.** Она собирается в файл, названный ключом `-o`, и рабочей
папке не принадлежит: собрать её можно сколько угодно раз и в любой формат,
`--only build` за это денег не берёт.

**Оригинала.** Конвейер читает исходный файл при каждом запуске и держит
разбор в `book.json`. Унесли папку без книги — пересобрать перевод не выйдет.
